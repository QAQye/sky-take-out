## SQL模糊查询

SQL 中模糊查询使用 **`LIKE`**，配合 `%` 或 `_` 来匹配。

以员工表 `employee`、姓名字段 `name` 为例：

| 需求               | SQL 条件           | 可以匹配           |
| ------------------ | ------------------ | ------------------ |
| 姓名包含“张”       | `name LIKE '%张%'` | 张三、小张、张小明 |
| 姓名以“张”开头     | `name LIKE '张%'`  | 张三、张小明       |
| 姓名以“张”结尾     | `name LIKE '%张'`  | 小张               |
| 姓名是“张”加一个字 | `name LIKE '张_'`  | 张三、张飞         |

使用模糊查询可以更具用户输入的关键词进行检索

## MyBatis中的自动赋值

 `#{name}` 到底怎么取值？

假设你传入的对象是：

```
EmployeePageQueryDTO dto = new EmployeePageQueryDTO();
dto.setName("张");
dto.setPage(1);
dto.setPageSize(10);
List<Employee> employees = employeeMapper.querry(dto);
```

调用时，你把 `dto` 对象交给了 Mapper 方法。MyBatis 会按照 SQL 中的 `#{name}`，读取这个对象的 `name` 属性，通常通过它的 getter：

```
dto.getName()  // 得到 "张"
```

**`#{name}` 不是数据库字段，也不是 Java 变量本身，而是 MyBatis 的参数占位写法。**

MyBatis 实际上会把 SQL 处理成类似：

```
SELECT * FROM employee WHERE name LIKE CONCAT('%', ?, '%')
```

然后将 `"张"` 绑定到 `?` 的位置，再交给数据库执行。

相当于mybatis可以自动解析做属性的绑定，其中在定义类中属性的名称要和绑定属性的名称要是相同的

解决方案：使用pagehelper和pageinfo可以解决这个问题

使用这两个技术的前提是在pom文件中已经引入了这两个库的相关依赖

```
<dependency>
    <groupId>com.github.pagehelper</groupId>
    <artifactId>pagehelper</artifactId>
    <version>最新版本</version>
</dependency>
```

你的项目已经引入了 `pagehelper-spring-boot-starter`，所以可以直接导入使用。

```
import com.github.pagehelper.PageHelper;
import com.github.pagehelper.PageInfo;
```

**1. PageHelper：设置分页，让插件在查询时进行分页**

```
PageHelper.startPage(2, 10);
```

表示接下来的查询要取**第 2 页，每页 10 条**，页码从 `1` 开始。

这行代码本身还没有查询数据库。执行下一行 Mapper 查询时，插件才会拦截 SQL，根据数据库类型进行分页，默认还会查询符合条件的总记录数。[官方用法说明](https://github.com/pagehelper-org/Mybatis-PageHelper/blob/master/wikis/zh/HowToUse.md)

```
PageHelper.startPage(2, 10);
List<Employee> employees = employeeMapper.querry(employeePageQueryDTO);
```

注意事项：

对，**`PageHelper.startPage(...)` 要放在你需要分页的 Mapper 查询之前，通常紧挨着写：**

```
// ① 设置分页：第 2 页，每页 10 条
PageHelper.startPage(2, 10);

// ② 执行查询，插件会自动对这次查询进行分页
List<Employee> employees = employeeMapper.querry(employeePageQueryDTO);
```

如果放在数据库查询之后那么就不会做分页了

并且**`startPage` 影响的是同一线程中紧接着的第一个 MyBatis 查询**，所以应放在目标查询前面，中间不要插入其他查询。

**2. PageInfo：整理查询结果和分页信息**

```
PageInfo<Employee> pageInfo = new PageInfo<>(employees);
```

它不会再去查询数据库，而是把已有的结果整理成一个方便读取的对象：

| 方法            | 含义               | 上面例子的结果      |
| --------------- | ------------------ | ------------------- |
| `getList()`     | 当前页员工列表     | 第 2 页的 10 名员工 |
| `getTotal()`    | 符合条件的总记录数 | `35`                |
| `getPageNum()`  | 当前页码           | `2`                 |
| `getPageSize()` | 每页条数           | `10`                |
| `getPages()`    | 总页数             | `4`                 |

其中**`employees` 只有 10 条，PageInfo 怎么知道总共 35 条？**

因为在插件正常生效时，虽然变量声明为 `List<Employee>`，实际返回对象是插件的 `Page<Employee>`。它除了保存员工数据，还携带总记录数等信息，`PageInfo` 会读取这些信息。[官方用法及示例](https://github.com/pagehelper-org/Mybatis-PageHelper/blob/master/wikis/zh/HowToUse.md)

因此：

```
employees.size();     // 当前页条数：10
pageInfo.getTotal();  // 所有匹配记录的总数：35
```

因此最终修改这一段代码可以修改成这样：

```
import com.github.pagehelper.PageHelper;
import com.github.pagehelper.PageInfo;

@Override
public PageResult querry(EmployeePageQueryDTO employeePageQueryDTO) {
    PageHelper.startPage(
        employeePageQueryDTO.getPage(),
        employeePageQueryDTO.getPageSize()
    );

    List<Employee> employees = employeeMapper.querry(employeePageQueryDTO);
    PageInfo<Employee> pageInfo = new PageInfo<>(employees);
    
    return new PageResult(pageInfo.getTotal(), employees);

}
```

先用pagehelper完成对拆线呢数据的分页操做，之后使用pageInfo来对查询的page对象进行封装处理，之后返回结果。

其实分页草错如果不使用Pageinfo也可以直接使用Page

```
import com.github.pagehelper.Page;
import com.github.pagehelper.PageHelper;

public PageResult querry(EmployeePageQueryDTO dto) {
    Page<Employee> page = PageHelper.startPage(
        dto.getPage(),
        dto.getPageSize()
    );

    List<Employee> employees = employeeMapper.querry(dto);
    
    return new PageResult(page.getTotal(), employees);

}
```

如果没有pagehelper那么就需要这样分开写

```
// 查询当前页员工
@Select({
    "<script>",
    "SELECT * FROM employee",
    "<where>",
    "<if test=\"name != null and name != ''\">",
    "name LIKE CONCAT('%', #{name}, '%')",
    "</if>",

    "</script>"

    @Param("name") String name,
    @Param("offset") int offset,
    @Param("pageSize") int pageSize
);

// 查询符合条件的员工总数
@Select({
    "<script>",
    "SELECT COUNT(*) FROM employee",
    "<where>",
    "<if test=\"name != null and name != ''\">",
    "name LIKE CONCAT('%', #{name}, '%')",
    "</if>",
    "</where>",
    "</script>"
})
long count(@Param("name") String name);
```

然后在 Service 中计算偏移量并调用：

```
@Override
public PageResult querry(EmployeePageQueryDTO dto) {
    int page = dto.getPage();
    int pageSize = dto.getPageSize();

    if (page < 1 || pageSize < 1) {
        throw new IllegalArgumentException("页码和每页条数必须大于 0");
    }

    // 例如第 2 页，每页 10 条：offset = 10
    int offset = (page - 1) * pageSize;

    // 当前页数据
    List<Employee> records = employeeMapper.queryPage(
        dto.getName(), offset, pageSize
    );

    // 符合条件的总记录数
    long total = employeeMapper.count(dto.getName());

    return new PageResult(total, records);
}
```

### 前端的时间显示问题

因为在后端中传递给前端的数据中返回的updatetime格式是这个样式的造成了前端不能够正确显示

![image-20260928215101265](C:\Users\24861\AppData\Roaming\Typora\typora-user-images\image-20260928215101265.png)

这个问题出现的原因是因为后端要查询到用户数据返回给前端，在用户使用查询数据查询到之后，使用的是Emloyee中的实体数据返回给前端，而后端中Emloyee那个实体又缺少日期格式对象的注解或者缺少日期转换器。

```
数据库中的日期时间
    ↓ MyBatis 查询并映射
Employee 中的 LocalDateTime 对象
    ↓ Jackson 序列化为 JSON（日期显示格式在这里决定）
前端接收到数据并显示
```

`LocalDateTime` 保存的是年、月、日、时、分、秒这些信息，**它本身不是带有固定显示格式的字符串**。要输出成 `"2026-09-22 22:53:56"`，需要在转换为 JSON 时指定格式。

因此这里有两种修改方式

+ 方案一：在要传递给前端的数据中加入注解@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")

+ 方案二：扩展SpringMVc的消息转换器

在这个类中可以通过实现实现父类方法extendMessageConverters来进行扩展消息转化器

![image-20260928223152035](C:\Users\24861\AppData\Roaming\Typora\typora-user-images\image-20260928223152035.png)

自己创建一个扩展消息转化器的类

```
/**
 * 对象映射器:基于jackson将Java对象转为json，或者将json转为Java对象
 * 将JSON解析为Java对象的过程称为 [从JSON反序列化Java对象]
 * 从Java对象生成JSON的过程称为 [序列化Java对象到JSON]
 */
public class JacksonObjectMapper extends ObjectMapper {

    public static final String DEFAULT_DATE_FORMAT = "yyyy-MM-dd";
//    这里是用的是年月日时分秒
    //public static final String DEFAULT_DATE_TIME_FORMAT = "yyyy-MM-dd HH:mm:ss";
//    这里转换的是年月日时分
    public static final String DEFAULT_DATE_TIME_FORMAT = "yyyy-MM-dd HH:mm";
    public static final String DEFAULT_TIME_FORMAT = "HH:mm:ss";

    public JacksonObjectMapper() {
        super();
        //收到未知属性时不报异常
        this.configure(FAIL_ON_UNKNOWN_PROPERTIES, false);

        //反序列化时，属性不存在的兼容处理
        this.getDeserializationConfig().withoutFeatures(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES);

        SimpleModule simpleModule = new SimpleModule()
                .addDeserializer(LocalDateTime.class, new LocalDateTimeDeserializer(DateTimeFormatter.ofPattern(DEFAULT_DATE_TIME_FORMAT)))
                .addDeserializer(LocalDate.class, new LocalDateDeserializer(DateTimeFormatter.ofPattern(DEFAULT_DATE_FORMAT)))
                .addDeserializer(LocalTime.class, new LocalTimeDeserializer(DateTimeFormatter.ofPattern(DEFAULT_TIME_FORMAT)))
                .addSerializer(LocalDateTime.class, new LocalDateTimeSerializer(DateTimeFormatter.ofPattern(DEFAULT_DATE_TIME_FORMAT)))
                .addSerializer(LocalDate.class, new LocalDateSerializer(DateTimeFormatter.ofPattern(DEFAULT_DATE_FORMAT)))
                .addSerializer(LocalTime.class, new LocalTimeSerializer(DateTimeFormatter.ofPattern(DEFAULT_TIME_FORMAT)));

        //注册功能模块 例如，可以添加自定义序列化器和反序列化器
        this.registerModule(simpleModule);
    }
}
```

之后返回在配置类中进行创建消息转换器对象，之后将自己的转换器设置为对象转换器，最后将自己的消息转化器放入整个容器中并且为其设置一个优先级
