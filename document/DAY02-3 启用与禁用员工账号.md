# DAY02-3 启用与禁用员工账号

## 需求分析与设计

业务规则：

+ 可以对状态为启用的员工账号做禁用操作
+ 可以对状态为禁用的员工状态做启用操作
+ 如果状态是禁用状态那么该用户不能登录系统

## 接口设计

在接口文档中如果请求参数如果是Querry类型和body类型是不是不同，Query类型的参数是放在浏览器访问的路径之中，而body参数是放在请求体之中，然后参数的类型和参数传递的方式没有关系，不管是post，get，put还是delete请求都可以是querry或者body类型，这个只是代表参数的位置，和传递参数的方法没有关系

在写接口的时候有几个核心的概念：请求方法，参数位置，参数类型

### 请求方法

就是 `GET`、`POST`、`PUT`、`PATCH`、`DELETE`，它们表达请求的语义。

| 请求方法 | 常见用途           | 常见传参位置                 |
| -------- | ------------------ | ---------------------------- |
| GET      | 查询数据           | Path、Query                  |
| POST     | 创建数据、提交操作 | Path、Query、Body            |
| PUT      | 整体替换或设置资源 | Path、Query、Body            |
| PATCH    | 局部修改资源       | Path、Query、Body            |
| DELETE   | 删除资源           | Path、Query；通常不使用 Body |

这些是常见约定。**不能根据“参数在 URL 里还是请求体里”，判断请求方法。**

GET 和 DELETE 请求体没有通用定义的语义，一些客户端、服务器或中间组件可能不支持或拒绝，所以实际设计时应避免依赖它们，尤其是 GET。

这些是请求的方法，前后端请求的方法和路径必须要一致，否则传递数据失败

### 参数位置

主要解决的是数据放在哪里的问题，比如上面

```
POST /admin/employee/status/0?id=10
```

接口文档里的 **Path、Query、Body 指的是参数位置**，并不是数据类型。

| 参数位置 | 含义                 | 示例                     | Spring 常用接收注解        |
| -------- | -------------------- | ------------------------ | -------------------------- |
| Path     | 放在 URL 路径中      | `/employee/10` 中的 `10` | `@PathVariable`            |
| Query    | 放在 URL 的 `?` 后面 | `?id=10&status=0`        | `@RequestParam`            |
| Body     | 放在请求体中         | `{"id":10,"status":0}`   | JSON 通常用 `@RequestBody` |

**同一个请求可以同时包含 Path、Query 和 Body。** 它们并不互斥，具体用哪些由接口文档约定。

另外，URL 不只是浏览器地址栏才会使用，前端代码、接口测试工具等发请求时也会使用 URL。

注意！！！！！接受的注解只能放在定义函数的括号中，不能在函数体中写作为一个局部变量

### 数据类型

数据类型指的是：

```
整数、字符串、布尔值、数组、对象……
```

例如，员工编号 `id` 是整数，它既可以放在 Query 中：

```
POST /admin/employee/status/0?id=10
```

也可以在另一种接口设计中放在 JSON Body 中：

```
POST /admin/employee/changeStatus
Content-Type: application/json

{
  "id": 10,
  "status": 0
}
```

这两种设计都可以，但**调用一个已经定义好的接口时，不能随意更换参数位置**。后端如果从 Query 接收 `id`，你只在 JSON Body 中传 `id`，通常就接收不到。

补充一点：**Body 不等于 JSON**。请求体还可以承载表单、文件等内容，`Content-Type` 用来说明其格式。例如 `application/json` 表示 JSON。

**目前可以按下面这张表选择接收方式：**

| 前端怎么传                             | 后端怎么接                                             |
| -------------------------------------- | ------------------------------------------------------ |
| JSON Body：`{"name":"张三"}`           | `@RequestBody EmployeeDTO dto`                         |
| 单个 Query 参数：`?id=10`              | `@RequestParam("id") Long id`                          |
| 多个 Query 参数：`?page=1&pageSize=10` | `EmployeePageQueryDTO dto`，通常省略 `@ModelAttribute` |
| Path 参数：`/employee/10`，对应 `{id}` | `@PathVariable("id") Long id`                          |
